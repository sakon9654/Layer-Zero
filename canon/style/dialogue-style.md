# Dialogue Style Canon — บทสนทนาที่ฟังเป็นมนุษย์

> เอกสารนี้เป็น **style canon** สำหรับการเขียนและรีไรต์บทสนทนาทุกตอน โดยเฉพาะ ARC 04 เป็นต้นไป  
> เป้าหมายไม่ใช่เลียนบทสนทนาจริงทุกคำ แต่ทำให้ผู้อ่านรู้สึกว่า **ตัวละครกำลังคุยกันจริงในสถานการณ์นั้น** ไม่ใช่กำลังพูดข้อมูลให้ผู้อ่านฟัง

# 1. กฎสูงสุด: Dialogue is not a report transcript

ตัวละครไม่พูดเพื่อให้ผู้อ่าน “ได้รับข้อมูลครบ” แต่พูดเพื่อทำสิ่งใดสิ่งหนึ่งในฉาก เช่น:
- ขอ
- ปฏิเสธ
- เตือน
- กดดัน
- หลบคำถาม
- ปกปิด
- ตรวจสอบ
- ให้กำลังใจ
- ตัดบท
- ซื้อเวลา
- ยืนยันความเข้าใจ
- ขอคำสั่ง
- รายงานเฉพาะสิ่งที่อีกฝ่ายจำเป็นต้องรู้ตอนนั้น

ถ้าประโยคมีอยู่เพียงเพราะผู้เขียนต้องการอธิบายข้อมูล ให้พิจารณาย้ายข้อมูลไป narration, action beat, เอกสาร, จอ, หรือแบ่งออกเป็นหลายจังหวะสนทนาแทน

---

# 2. คนที่รู้อยู่แล้วไม่พูดข้อมูลให้กันซ้ำ

ห้ามใช้บทพูดแบบ:
- “อย่างที่คุณรู้…”
- “จากที่เราคุยกันเมื่อวาน…”
- การสรุป protocol ทั้งชุดให้คนในทีมที่ใช้ protocol นั้นทุกวัน
- การเรียกชื่อ/ตำแหน่งซ้ำทุกประโยคเพียงเพื่อบอกผู้อ่านว่าใครมีอำนาจสูงกว่า

ถ้าทั้งสองฝ่ายรู้บริบทอยู่แล้ว ให้พูดเฉพาะ **ข้อมูลใหม่ / จุดที่ขัดแย้ง / การตัดสินใจ**

ตัวอย่าง:
- แข็ง: “คุณรินครับ กล้อง B-4 ซึ่งเป็นกล้องที่เราตั้งไว้เฝ้า Object หยุดส่งภาพครับ”
- ธรรมชาติ: “คุณริน กล้อง B-4 ดับครับ”
- ต่อเนื่อง: “เมื่อไร” / “สิบวินาทีที่แล้วครับ”

---

# 3. Honorific เป็นจังหวะ ไม่ใช่ suffix

ลำดับอำนาจยังเป็น canon:
- อธิคม = หัวหน้าสาขา
- ริน = หัวหน้าทีมภาคสนาม
- พิม/เอก = ทีมภาคสนามตามหน้าที่
- นนท์ = ผู้เข้ารับการประเมินภาคปฏิบัติแบบจำกัด ยังไม่ใช่เจ้าหน้าที่

แต่คำเรียกใช้ตามจังหวะ:
- “คุณริน” ใช้เมื่อเรียกความสนใจ, เริ่มบทสนทนาใหม่, เริ่มรายงานจากอีกจุด, หรือเมื่อต้องชี้ผู้รับให้ชัด
- เมื่อคุยต่อเนื่องแล้ว ใช้ “ครับ/ค่ะ/รับทราบ/เจอแล้ว/ยังครับ” ได้
- รินเรียก “พิม / เอก / นนท์” ได้โดยตรง
- รินพูดกับอธิคมด้วยน้ำเสียงของผู้ใต้บังคับบัญชาที่มีอำนาจภาคสนามของตัวเอง: รายงาน/เสนอ/ขออนุมัติเมื่อเกินขอบเขต ไม่ใช่พูดราชการแข็งทุกประโยค
- ใน narration ใช้ ริน/พิม/เอก/อธิคม/นนท์ ตามปกติ

**ห้ามแก้บทพูดโดยค้นหาแล้วเติม “คุณ” แบบกลไก**

---

# 4. เสียงพูดต้องแยกตัวละครได้แม้ไม่มี dialogue tag

## ริน
- สั้นและตรง เพราะใช้คำเพื่อให้คนทำงานต่อได้
- ถ้ารู้ไม่พอ จะพูดว่าไม่รู้ ไม่แต่งคำปลอบ
- ถามเพื่อให้ได้ข้อมูลที่ใช้ตัดสินใจ
- ในภาวะฉุกเฉินยิ่งสั้น
- ไม่อธิบาย tactical reasoning ทุกครั้ง; การกระทำแสดงความชำนาญแทน
- อารมณ์ขันแห้งได้ แต่ไม่ใช่ทุกฉาก

ตัวอย่างโทน:
- “เห็นเองไหม”
- “งั้นยังไม่ยืนยัน”
- “ถอยก่อน”
- “เอาชื่อ ไม่เอาจำนวน”

## พิม
- แม่น แต่ไม่พูดเหมือนรายงานวิจัยตลอดเวลา
- มักแก้ “ระดับความแน่ใจ” มากกว่าแก้ทุกคำ
- ถ้าข้อมูลชัด ตอบสั้นได้
- มีอารมณ์ขันเบา/แห้งกับนนท์เมื่อแรงกดดันไม่สูง

ตัวอย่าง:
- “เห็นค่ะ แต่ยังไม่รู้ว่าเกี่ยวกัน”
- “ภาพบอกได้แค่นั้น”
- “อันนั้นนายกำลังเดา”

## เอก
- ประหยัดคำ
- รายงานสิ่งที่ต้องใช้ทันที
- ใช้คำสุภาพ แต่ไม่พูดชื่อผู้รับซ้ำ
- มุกหน้าตายควรเกิดในช่วงผ่อน ไม่ใช่ตอนชีวิตกำลังเสี่ยง

ตัวอย่าง:
- “เจอแล้วครับ”
- “ประตูยังใช้ได้”
- “ขาดหนึ่งคนครับ”

## นนท์
- เป็นคนธรรมดาที่กำลังเรียนรู้ protocol ไม่ใช่เจ้าหน้าที่เก๋า
- ถามจากสิ่งที่คนธรรมดาจะสงสัย
- พูดเล่นเพื่อคลายแรงกดดันได้ แต่เวลาอันตรายจริงจะสั้นลง
- เมื่อเรียนรู้แล้ว ให้เห็นจากการหยุดตัวเอง/รายงานก่อน มากกว่าพูดศัพท์สำนักงานคล่อง

ตัวอย่าง:
- “ถ้าไม่ใช่มัน แล้วอะไรทำรอยนี้”
- “ผมเห็น แต่ไม่รู้ว่าใช่อันเดียวกันไหม”
- “โอเค ผมไม่เข้าไป”

## อธิคม
- ถามเพื่อหาจุดตัดสินใจ ไม่ใช่ขอ exposition
- ประโยคสั้นได้ เพราะรู้ระบบและไว้ใจรินในงานภาคสนาม
- สนใจสถานะ, ความเสี่ยง, สิ่งที่รินเสนอ, ทรัพยากร/การอนุมัติที่ต้องใช้
- ไม่ micromanage มุมยิง/ตำแหน่งคน/การเคลื่อนของทีมจากระยะไกล

ตัวอย่าง:
- “มีคนเจ็บไหม”
- “ข้อเสนอ”
- “รับ เดี๋ยวส่งคนเพิ่ม”
- “ถ้ามีอะไรเปลี่ยน รายงานทันที”

---

# 5. Subtext ก่อนคำอธิบายตรง

ถ้าความสัมพันธ์หรืออารมณ์สามารถแสดงด้วย:
- การไม่ตอบ
- เปลี่ยนเรื่อง
- ตอบสั้นกว่าปกติ
- action beat
- การเลือกคำ
- คนหนึ่งเข้าใจสิ่งที่อีกคนไม่พูด

ให้ใช้ก่อนการพูดตรง ๆ

ตัวอย่างรินเรื่องอดีต:
- ไม่ควร: “อดีตของฉันเป็นเรื่องที่ฉันยังมีบาดแผลและไม่อยากเล่า”
- ควร: “ไว้ถามวันอื่น” แล้วกลับไปทำงาน

---

# 6. เวลาฉุกเฉิน ประโยคหดสั้น

เมื่ออันตรายเพิ่ม:
- ตัดประธานที่รู้กัน
- ตัดคำอธิบาย
- ใช้คำสั่ง/คำยืนยันสั้น
- การพูดทับ/ขัดจังหวะทำได้
- ให้ action interrupt dialogue ได้

ตัวอย่าง:
“ประตู—”
“ทิ้งมัน ถอย!”

ไม่ควรให้คนพูดรายงานหลายบรรทัดขณะกำลังถูกไล่ ถ้าข้อมูลนั้นไม่จำเป็นต่อการเอาชีวิตรอดทันที

---

# 7. Dialogue beat ต้องมีแรงเสียดทานหรือการเปลี่ยนแปลง

ทุกช่วงสนทนาควรมีอย่างน้อยหนึ่งอย่าง:
- ข้อมูลใหม่
- ความเห็นไม่ตรง
- การตัดสินใจ
- สถานะเปลี่ยน
- ความสัมพันธ์เปลี่ยนเล็กน้อย
- ความเสี่ยงเพิ่ม/ลด
- สิ่งที่ตัวละครพยายามปิดบัง

ถ้าถาม–ตอบแล้วทุกอย่างเหมือนเดิม และไม่มี character beat ให้พิจารณาตัด

---

# 8. อย่าทำทุกคนให้ “แม่น” เท่ากัน

ภาษาสำนักงานที่แม่นเป็นคุณลักษณะของระบบ แต่แต่ละคนไม่ต้องพูดเหมือนรายงาน:
- พิมอาจใช้ถ้อยคำแม่นที่สุด
- รินแม่นเฉพาะจุดที่ส่งผลต่อการตัดสินใจ
- เอกพูดข้อมูลหน้างานสั้น
- นนท์อาจพูดคำกว้างก่อน แล้วเรียนรู้แก้ตัวเอง
- พลเรือนพูดตามความกลัว ความจำ และความเข้าใจของตัวเอง

ความคลาดเคลื่อนเล็ก ๆ ที่สมจริง **ไม่ใช่ continuity error** ถ้า narration/ทีมยังแยกข้อเท็จจริงได้

---

# 9. Protocol อยู่ใต้บทสนทนา ไม่ใช่บนหน้าบทสนทนา

สำนักงานมี protocol แต่คนที่ทำงานด้วยกันไม่จำเป็นต้องท่อง protocol ให้กัน

ให้แสดง protocol ผ่าน:
- รินสั่งชื่อแทนจำนวน
- เอกเริ่มอ่านชื่อโดยไม่ต้องมี exposition
- พิมแยกหลักฐานในบันทึก
- คนใหม่อย่างนนท์ถามเมื่อไม่เข้าใจ

กฎนี้สำคัญกับ ARC 04 เพราะการพยายามทำให้ hierarchy/protocol ชัดเกินไปทำให้บทสนทนาในตอน 03–05 แข็งและไม่เป็นมนุษย์

# 10. Read-aloud pass — บังคับใช้ก่อน approve

ก่อนตอนใดเปลี่ยนเป็น `approved` ให้ตรวจบทพูดด้วยเกณฑ์เสมือนอ่านออกเสียง:

1. คนจริงในสถานการณ์นี้มีเหตุผลจะพูดประโยคนี้หรือไม่
2. ถ้าตัดชื่อ/ตำแหน่งออก ยังรู้ไหมว่าใครพูดกับใคร
3. มีข้อมูลที่ทั้งสองฝ่ายรู้อยู่แล้วถูกพูดซ้ำเพื่อผู้อ่านหรือไม่
4. ประโยคยาวเกินระดับความเร่งด่วนหรือไม่
5. ตัวละครสองคนสามารถสลับประโยคกันโดยบุคลิกไม่เปลี่ยนหรือไม่ — ถ้าใช่ voice ยังไม่ชัด
6. มีประโยคไหน narration/action ทำหน้าที่แทนได้ดีกว่าหรือไม่
7. อ่านในใจแล้ว “เป็นภาษาเขียน” มากกว่าภาษาที่คนนี้จะพูดหรือไม่
8. คำสุภาพ/คำเรียกซ้ำจนได้ยินเป็น pattern หรือไม่

หากข้อใดตอบว่าใช่ ให้ rewrite ก่อน approve.

# 11. Thai prose implementation

- ไม่จำเป็นต้องเลียนคำฟุ่มเฟือยจริง เช่น “เอ่อ”, “แบบว่า”, “คือว่า” มากจนรบกวนจังหวะ
- ใช้ประโยคไม่สมบูรณ์ได้เมื่อบริบทรองรับ
- ประธานละได้เมื่อรู้กันว่าใครเป็นผู้กระทำ
- “ครับ/ค่ะ” ไม่ต้องติดทุกประโยค แต่ใช้รักษา voice และความสัมพันธ์
- ชื่อคนไม่ควรถูกใช้เป็นคำลงท้ายแทน punctuation
- dialogue tag ใช้เท่าที่จำเป็น; action beat ช่วยแสดงอารมณ์/จังหวะได้ดีกว่า adverb หลายกรณี
- คำอังกฤษภายในสำนักงาน เช่น Object ใช้ได้เมื่อเป็นศัพท์ที่ canon กำหนด แต่ไม่ควรทำให้พลเรือนหรือนนท์พูด jargon คล่องเกินบริบท

---

# 12. ARC 04 correction directive

ตอน 03–05 ต้องใช้เอกสารนี้เป็นฐานการรีไรต์:
- ลด “คุณริน” ที่เป็นเพียงคำลงท้าย
- ลด “รับทราบครับ/ค่ะ” ที่ซ้ำโดยไม่เพิ่มจังหวะ
- ลดบทพูดที่ท่องหลักฐานซึ่ง narration บอกได้
- ทำให้รินพูดสั้นลงในภาวะกดดัน
- คืนมุก/คำถามธรรมดาให้นนท์เมื่อสถานการณ์เปิดช่อง
- ให้พิมฟังเหมือนคนฉลาดและระวังข้อสรุป ไม่ใช่ระบบตรวจคำ

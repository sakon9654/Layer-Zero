# กฎการจัดเก็บและทำงานกับ Story Arc ทุก Arc

เอกสารนี้ใช้กับ Arc 01 และ Arc ถัดไปทั้งหมด อ่านร่วมกับ `AGENTS.md` ซึ่งเป็นกฎ Canon และการเขียนหลัก หากขัดกัน ให้ยึด `AGENTS.md` และคำตัดสินผู้เขียน

## 1. หนึ่ง Arc หนึ่งโฟลเดอร์

จัดเก็บที่ `story/arcs/arc-NN/` เช่น `arc-01/`, `arc-02/` โดยมีโครงสร้าง:

```text
story/arcs/arc-NN/
├── README.md                  # สารบัญ Arc และลำดับอ่าน
├── outline.md                 # โครงเรื่อง/จังหวะการเฉลย
├── entity-object-dossier.md   # ถ้ามี: รายการ Deviation ที่เกี่ยวข้อง
├── dossier-validation.md      # ถ้ามี: ผลตรวจรหัส/ความสอดคล้อง
└── chapters/
    ├── 01-chapter-title.md
    └── 02-chapter-title.md
```

สร้างไฟล์อื่นเมื่อจำเป็นและเพิ่มลิงก์ใน README; ไม่ต้องสร้าง dossier ว่างเพื่อให้ครบรูปแบบ

## 2. จุดเริ่มต้นและสารบัญ

- ก่อนสร้าง Arc ใหม่ คัดลอก `templates/arc-readme.md` เป็น `story/arcs/arc-NN/README.md`
- README ของ Arc ต้องมี: ชื่อ Arc, ลำดับอ่าน, ลิงก์โครงเรื่อง, ตอนที่มีจริงและสถานะ, ข้อมูลประกอบ, Canon ที่เกี่ยวข้อง และปม/ข้อควรระวังที่ยังเปิดอยู่เมื่อมี
- เพิ่มลิงก์ Arc ใหม่ใน `story/arcs/README.md` และปรับลิงก์ Arc ปัจจุบันใน README หน้าแรกเมื่อเปลี่ยน Arc
- ลิงก์เป็น relative path เพื่อให้ใช้งานบน GitHub ได้

## 3. ต้นฉบับและการตั้งชื่อ

- เก็บต้นฉบับหลักเพียงแห่งเดียวใน `story/arcs/arc-NN/chapters/`; ห้ามทำสำเนาคู่ขนานใน `manuscript/` โดยไม่มีเหตุผลและป้ายกำกับชัดเจน
- ใช้ชื่อ `01-chapter-title.md`, `02-chapter-title.md` เรียงตามลำดับการอ่าน เลขตอนเริ่มใหม่ในแต่ละ Arc
- ใช้อักษรอังกฤษตัวเล็กและขีดกลางสำหรับ slug; ชื่อตอนในเนื้อหาใช้ภาษาไทยได้
- ทุกตอนมี front matter อย่างน้อย `chapter`, `title`, `status`, `pov`, `timeline`; ใช้ `templates/chapter.md` เป็นจุดตั้งต้น แต่ต้นฉบับจริงไม่จำเป็นต้องคงหัวข้อวางแผนไว้
- สถานะ `outline`, `draft`, `approved` ต้องตรงกับการอนุมัติจริง ห้ามเลื่อนเป็น `approved` เอง

## 4. ขั้นตอนก่อนเขียน/แก้ตอน

1. อ่าน `AGENTS.md`, `canon/INDEX.md`, `story/arcs/arc-NN/README.md` และ `outline.md`
2. อ่านตอนก่อนหน้าและตอนที่เกี่ยวข้องใน Arc เดียวกัน รวมถึง Arc ก่อนหน้าเมื่อเนื้อหาต่อเนื่อง
3. อ่าน Canon โลก สำนักงาน ตัวละคร และ Deviation ที่เกี่ยวข้อง; อ่าน hidden Canon เฉพาะเพื่อรักษาความต่อเนื่อง ไม่เฉลยก่อนกำหนด
4. ตรวจ `canon/timeline/master-timeline.md` และ `notes/continuity.md`
5. หากพบข้อขัดแย้ง ให้แจ้งไฟล์และประเด็นแก่ผู้เขียน ห้ามเลือกแก้ Canon เองเงียบ ๆ

## 5. หลังเขียน/แก้ตอน

- อัปเดตลิงก์และสถานะใน README ของ Arc ในงานเดียวกัน
- ตรวจลำดับตอน POV เวลา สถานที่ สิ่งของที่ครอบครอง และความรู้ของตัวละคร
- ข้อเท็จจริงใหม่ในต้นฉบับร่างยังเป็นข้อเสนอ ไม่แก้ `canon/` หรือ master timeline ให้เป็นข้อเท็จจริงที่อนุมัติแล้วจนกว่าผู้เขียนยืนยัน
- หากมีปม/ความเสี่ยงด้าน continuity ให้บันทึกเป็นข้อสังเกต ไม่เฉลยความลับใน README ที่ใช้เป็นทางเข้าของผู้อ่านทั่วไป
- ไม่เปลี่ยนรหัส Deviation หรือคุณสมบัติของ Object/Entity เพื่อให้พล็อตเดินสะดวกโดยไม่มีการอนุมัติ

## 6. การทำงานบน Git

- เขียนไฟล์ใหม่ใน Arc ที่ถูกต้องตั้งแต่แรก
- เมื่อต้องย้ายไฟล์ ให้ตรวจว่าปลายทางตรงกับต้นฉบับก่อนลบไฟล์เดิม และแก้ลิงก์ที่อ้างถึง
- ใช้ commit message บอก Arc และการเปลี่ยนแปลง เช่น `draft arc 02 chapter 01`, `update arc 01 reading index`
- ไม่เปลี่ยน Canon หลักพร้อมกับย้ายไฟล์/จัดโครงสร้างโดยไม่ได้รับอนุญาต

## 7. ขอบเขต

Arc 01 เป็นตัวอย่างของโครงสร้าง ไม่ใช่แม่แบบบังคับเนื้อเรื่อง Arc ถัดไปอาจมีจำนวนตอน ตัวละคร POV และ dossier ต่างกันได้ โดยต้องรักษากฎ Canon และการจัดเก็บร่วมกัน

## 8. บันทึกเหตุการณ์ระหว่างร่าง Arc (ก่อนอนุมัติ)

- ก่อนเขียนตอนถัดไป ให้ตรวจต้นฉบับตอนก่อนหน้าใน Git จริง โดยเฉพาะฉากจบ วันเวลา สถานะบุคคล และตำแหน่งหลักฐาน ห้ามอาศัย outline แทนต้นฉบับที่เขียนแล้ว
- เก็บลำดับเหตุการณ์และสถานะสิ่งของ/ตัวละครที่เพิ่มใน **ตอน draft** ในไฟล์ continuity ของ Arc เช่น `story/arcs/arc-02/draft-continuity.md`; ใส่เลขตอนและวันที่ตามต้นฉบับ พร้อมระบุว่าเป็น `draft-only` ไม่ใช่ Canon ที่อนุมัติแล้ว
- เทียบกับ `canon/timeline/master-timeline.md` แต่ **ห้ามนำ draft ไปเพิ่มใน master timeline ในฐานะ established-canon**; ย้ายหรือสรุปเข้าสู่ Canon เมื่อผู้เขียน approve ตามหลักฐานของตอนที่อนุมัติ
- การบันทึกข้อความของ Object/Entity ต้องแยก “ปรากฏในหลักฐาน”, “คำกล่าว”, “ข้อสันนิษฐานทีม” และ “ความจริงที่พิสูจน์แล้ว”; การที่ระบบลงชื่อแทน ไม่ใช่หลักฐานความยินยอม
- ก่อนเขียนฉากใช้ Object ให้เปิด Canon คุณสมบัติของรหัสนั้นอีกครั้ง โดยเฉพาะข้อจำกัดและสิ่งที่ยังไม่ทราบ ห้ามยกระดับคำกล่าวของ Entity เป็นคำเฉลย
